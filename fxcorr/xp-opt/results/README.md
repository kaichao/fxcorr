# 正式结果

**当前口径（2026-11-15 起）**：单任务 = 一个 (batch, ds 组)，一个 xpp 进程。
下面的「单任务标定」是当前目标口径；「历史」一节是全批单进程口径的正式 run，
仅作对照。

## 目录规范

每个正式 run 由 `scripts/run_xp.sh --formal` 生成，远端在
`$XP_OPT_ROOT/results/<YYYYMMDD>/<run-id>/`，本地由 `sync_results.sh` 同步到
`results-detail/<YYYYMMDD>/<run-id>/`（gitignored）：

```text
manifest.json   数据集、batch、站数、OMP、镜像与 ID、主机、脚本 sha256、源码版本
result.tsv      一行标准结果（与 summary.tsv 同列）
metrics.json    阶段耗时、内存、指纹
command.sh      实际执行的完整 docker 命令
logs/           run.log / time.txt / timing-brief.tsv / mem-peak-bytes.txt
```

跨 run 汇总：`results/summary.tsv`（进 git；正式 run 自动追加）。
下表的 run-id 是 `results-detail/` 下的相对路径；详细文件不在 git 中。

条件：登录 `ssh p419-n1`，计算节点 `h04r1n07`（Hygon C86 7185，32 核

- **xp 的 `xmac` 几乎不随线程扩展**（P=1/2/4 为 27.70/27.58/27.55 s，
  P=8 才降到 15.75 s），其 wall 扩展主要来自 `station`（105.7→14.1，
  7.5×）。xpp 的 `xmac` 近线性（26.8→14.6→8.2→5.7 s），因此 P≥2 后
  同 P 的 xpp/xp 之比为 1.14×/1.33×/1.69×/1.64×——xpp 优势随线程数放大。
- 内存与 CPU：峰值 RSS xp 398 MiB、xpp 234 MiB（−41%）；P=8 时 user 时间
  xp 206.2 s、xpp 131.1 s。
- `read` 列 P=1 的 0.79 s 是页缓存热（sanity 刚跑过），其余约 1.5–1.7 s，
  占比可忽略。
- 与 p419-n0（11-16）对比：xp1 139.37 vs 139.81（−0.3%）；xpp P=8
  20.00 vs 18.57（+7.7%，本次两轮 21.4/19.4 s，在 xmac ±5–10% 的已知
  单次波动内；P=1/2/4 的 xpp 为 122.66/63.97/34.38 vs
  119.78/61.59/32.55，同向 +2.4%/+3.9%/+5.6%）。md5 两节点全部相同。
- 明细（每 run 的 wall/user/sys/RSS 与阶段耗时）：`results-detail/20261119-p419n1/matrix.tsv`。

- 单任务：`rc=0`；`.part` 存在且 md5 与 xp 相同；`metrics.json` 的

- 失败 run 也保留目录，`result.tsv` 的 status=fail。
